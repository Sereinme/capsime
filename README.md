# capsime

在 Windows 上用 **CapsLock** 一键切换中英文输入法。纯 Rust 实现，单文件、无依赖、托盘常驻。

> caps = CapsLock，ime = Input Method Editor（输入法）。CapsLock 常年吃灰，干脆让它干点正事。

## 特性

- **CapsLock 切换中英文**：单独按一下 CapsLock = 切换中/英。大写锁状态与指示灯不会变化（按键被拦截，不触达系统）。
- **不劫持组合键**：`Ctrl/Alt/Shift/Win + CapsLock` 一律放行，保留系统原生行为。
- **轻量**：单个 exe（约 433 KB），Windows 子系统（无控制台窗口），常驻工作集约 11 MB、
  私有内存约 1.6 MB，事件驱动、零轮询（实测见「性能」一节）。
- **稳定**：钩子回调只做最少工作，耗时的输入法调用在工作线程执行，前台程序卡死也不会拖慢钩子。
- **托盘菜单**：启用/暂停、开机自动启动、查看日志、退出。
- **可排查**：每次切换（方式、结果、前台程序）都写日志；自带 `--selftest` 冒烟自检。
- **安全**：不联网、不需要管理员权限、不注入其他进程；只拦截 CapsLock 一个键。

## 使用

1. 运行 `capsime.exe`，托盘出现一枚**圆角方形图标**，上面是字母 **C**（CapsLock 的 C）：
   圆环主体是几何的，右下扫出一笔**朱砂色**的书法收锋。配色与阴影参考 Apple 的图标语言，
   并且**跟随系统的亮/暗模式自动切换**（纸白底墨 C / 靛蓝底白 C）。
2. 在任意程序里按一下 **CapsLock**，中英文来回切换。
3. 右键托盘图标：
   - **启用大写键切换**：临时暂停/恢复拦截（暂停后 CapsLock 恢复原生大写锁功能，
     整套图标转冷灰）。
   - **开机自动启动**：写/删注册表 `HKCU\...\CurrentVersion\Run`，只影响当前用户。
   - **查看日志**：打开 `%LOCALAPPDATA%\capsime\capsime.log`。
   - **退出**：卸载钩子后退出。

重复启动会被单实例互斥锁挡住，静默退出。

### 命令行

```
capsime                 启动（托盘常驻）
capsime --selftest [秒]  冒烟自检：装钩子、投递一次切换、自动退出（默认 3 秒）
capsime --version       显示版本
capsime --help          显示帮助
```

`--selftest` 适合"程序看起来没反应"时快速定位：能打印 `OK: 键盘钩子已安装` 说明钩子没问题，若失败会有明确的错误码（常见是安全软件拦截）。

## 工作原理

```
CapsLock 按下
   │
   ▼
主线程：WH_KEYBOARD_LL 低级键盘钩子
   │  · 只在"无修饰键 + 物理按键 + 非长按重复"时拦截
   │  · 吞掉按下/抬起 → 大写锁状态与指示灯不变
   │  · 只做 PostMessage(WM_SWITCH)，立刻返回（避免钩子超时被系统移除）
   ▼
工作线程：对前台窗口切换中英文，逐级兜底
   1. IMM 上下文（ImmGetContext / ImmSetConversionStatus）    ← 本进程窗口才有，可读可写可核对
   2. 注入输入法自带的中英文切换键 Ctrl+Space                ← 主路径，对任何程序都适用
      · 一次按键只注入一次，不做无依据的重试（重试会把状态翻回去 = 按了没反应）
      · 若系统把这次按键当成"切换输入语言"：切成中文/英文布局算成功；
        切成无关语言（如日文）立刻切回，转用 3
   3. 键盘布局切换：WM_INPUTLANGCHANGEREQUEST（≈ Win+Space）  ← 最后的兜底，需装有英文布局
   ▼
写日志：方式、切换后状态（读得回时）、是否核对过、前台程序名
```

"中文态"的判定：IME 处于打开状态 **且** 转换模式带 `IME_CMODE_NATIVE` 位。

### 托盘图标："变形 C" + 亮暗主题

图标是字母 **C**（CapsLock 的 C）：圆环主体是几何的，环的下端顺势扫出一笔由粗到细的
**朱砂收锋**（传统印泥色 = 中文书写的意象），一个字形里"几何 + 墨"并置。
材质参考 Apple 应用图标：超椭圆 squircle 底、竖向渐变 + 顶部径向柔光、顶缘高光、
图形底下压一层偏移的深色副本当柔和投影。

- **主题**：主线程有一个**隐藏的顶层窗口**（消息窗口收不到系统广播），
  系统切换亮/暗模式时会广播 `WM_SETTINGCHANGE`，收到后重读
  `HKCU\...\Themes\Personalize\AppsUseLightTheme` 并换图标——亮色是纸白底墨 C，
  暗色是靛蓝底白 C，朱砂收锋两侧都用。事件驱动，不轮询。
- **暂停**：托盘菜单暂停拦截时整套转冷灰，形状不变。

### 为什么要靠"注入切换键"，而不是直接设置 IME 状态

在 Windows 11 + 微软拼音 + 记事本上逐条实测过（判据是**打字结果**，不是任何 API 的返回值）：

- `ImmGetContext` 对**别的进程一律返回 NULL**（Notepad / Qt / Electron / 资源管理器 / UWP 全是），
  既读不到状态也设不了，做不了主力。
- 前台线程的默认 IME 窗口（`ImmGetDefaultIMEWnd`）**读回来的不是真实状态**：记事本明明在中文态
  （打字出「你好」），`IMC_GETCONVERSIONMODE` 却给出 `0x0001`、`IMC_GETOPENSTATUS` 给出 0
  （看上去是英文），而且注入切换键后它纹丝不动。往这个窗口发 `IMC_SETCONVERSIONMODE` 更糟：
  只改它自己的读回值，前台程序毫无变化——这正是"日志说切了、实际没切"的根源。
- **注入 `Ctrl+Space` 真的有效**：记事本里能从英文切成中文（`nihao` → 「你好」），经典窗口、
  跨进程同样有效。按键由输入法在**目标程序自己的上下文**里处理，所以对任何程序都适用。

这台机器上实测有效的清单（`cargo run --example ime_probe` 可复现）：
`IMM 直接设置`、`默认 IME 窗口设置`、`注入 Ctrl+Space` 三条里，只有前两条会"看起来生效"，
真正能改变前台程序行为的只有 `Ctrl+Space`；`Shift`、单独 `Ctrl`、`IME_ON/IME_OFF` 虚拟键、
`ImmSimulateHotKey`、`VK_KANA` 均无效。

## 兼容性与已知限制

- 支持 Windows 10 / 11（x64）。
- 默认走"注入输入法中英文切换键（Ctrl+Space）"，所以**输入法里必须把这个键配置为切换中英文**
  （微软拼音默认如此）。若你把它设成了"无"，就切不动了，这时请改用别的键位方案。
- **日志里的"未核对"是正常的**：现代程序（TSF 输入法）读不回输入法状态，工具只能如实标注，
  所以别拿日志当"切没切"的判据——看屏幕上的输入法状态。
- 想确认这台机器上到底哪条路径有效，跑 `cargo run --example ime_probe`（进程内逐条实测）；
  想在真实应用里验证切换链路，跑 `cargo run --example ime_probe -- --notepad`
  （会新开一个记事本，靠"打字出 你好 还是 nihao"来判定，最可信）。
- 注入的 `Ctrl+Space` 会被输入法消费；如果某个程序完全没启用输入法，这次按键可能落到程序自己的
  Ctrl+Space 快捷键上（例如编辑器里的"触发补全"）。
- UAC 安全桌面（提权弹窗界面）上的按键收不到，属于系统机制；不影响已登录桌面内的使用。
- 部分带内核级反作弊的游戏可能屏蔽全局键盘钩子，此时在游戏内无效（不影响系统其他程序）。
- 因为拦截了 CapsLock，想临时用原生大写锁：托盘菜单暂停，或用 `Shift+CapsLock` 组合键
  （组合键不拦截，但注意它同时会关闭大写锁，属于系统原生行为）。

## 性能

本机（Windows 11，x64，Rust 1.99 release 构建）实测，2026-10-17：

| 指标 | 实测值 |
| --- | --- |
| 空闲内存 | 工作集 10.9 MB，私有字节 1.6 MB（启动后即稳定，峰值与空闲相同） |
| 空闲 CPU | 15 秒采样内增长 0 ms（0.0000% of one core）——事件驱动，无轮询 |
| 线程数 / 句柄数 | 2 个线程（主线程 + 切换工作线程）/ 142 个句柄 |
| 单次切换处理耗时 | 105～123 ms（min/avg/max = 105.3 / 110.4 / 122.6），其中 100 ms 是刻意等待
「让系统和输入法处理完这次按键，再检查键盘布局是否被当成语言切换」；注入本身在 1 ms 内完成，
所以按下 CapsLock 到输入法状态变化是**立即**的，这 100 ms 只是工作线程的收尾与写日志 |
| 每次切换 CPU | 约 0.8 ms（含一次日志文件的打开/写入） |
| 连打 100 次开关后 | 工作集 / 私有字节 / 句柄数 / 线程数**完全不变**（无泄漏） |
| 启动到托盘就绪 | < 1 s（日志三条启动信息落在同一秒） |
| release 体积 | 442,880 字节（LTO + strip） |

测量方式：对正在运行的实例，每按一次就向它的切换工作线程投递一次 `WM_SWITCH`
（与 CapsLock 触发的路径完全一致），用日志落盘时间计时；内存/句柄/CPU 由
`Get-Process` 采样。前台程序卡死时，读状态的两条消息各带 250 ms 超时，
工作线程最多多花约 0.5 s，但不会影响钩子线程和系统输入。

钩子回调本身只做"是不是 CapsLock + 有没有修饰键"的判断和一次 `PostMessage`，
不做任何输入法调用：普通按键只是两次原子读加一个整数比较，因此全局打字速度不受影响，
也不会触发系统的 `LowLevelHooksTimeout`（默认 300 ms，我们差四个数量级）。

## 构建

需要 Rust 工具链（MSVC 或 GNU 均可）。本项目在 GNU 工具链下开发：

```powershell
# 依赖：rustup + mingw（GNU 链接器）；MSVC 工具链同样可用
cargo build --release
# 产物：target\release\capsime.exe（含 LTO 与 strip，体积约几百 KB）
```

常用命令：

```powershell
cargo fmt
cargo clippy
cargo test
cargo run --example icon_preview   # 托盘图标验收图：尺寸 × 启用/暂停 × 亮/暗
cargo run --example ime_probe             # 输入法切换排查：环境 + 逐条路径实测
cargo run --example ime_probe -- --notepad # 真实记事本里验证"打字结果"，最可信
cargo run --example ime_probe -- --e2e     # 对着另一个真实进程验证切换链路
```

## 项目结构

```
src/
  main.rs       入口（--version/--help/--selftest 及托盘模式分发）
  lib.rs        模块声明
  app.rs        单实例、双线程消息循环、装配与生命周期
  hook.rs       WH_KEYBOARD_LL 钩子：只拦截单独按下的 CapsLock
  switcher.rs   中英文切换：读状态 + 注入切换键 + 逐级兜底与核对（含单元测试）
  tray.rs       托盘图标与菜单
  autostart.rs  开机自启（HKCU Run 项，含单元测试）
  icon.rs       托盘图标：变形 C（几何圆环 + 朱砂收锋），跟随亮/暗主题（含单元测试）
theme.rs      系统亮/暗模式检测（读 AppsUseLightTheme）
  log.rs        极简文件日志（512KB 轮转）
  util.rs       Win32 小工具（含单元测试）
examples/
  icon_preview.rs  托盘图标验收图生成（尺寸 × 状态 × 任务栏底色）
  ime_probe.rs     输入法切换排查工具（环境检查 / 逐条路径实测 / 跨进程验证）
assets/
  icon/capsime-icon.svg  图标设计稿（512 单位；可在 VectorCraft / Inkscape 里继续编辑）
```
